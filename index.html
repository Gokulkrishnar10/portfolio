Project 02

ITOC — Intelligent Task Orchestration
& Monitoring System

FastAPI · LLaMA 3.3 70B · scikit-learn · APScheduler · Real-Time ML Pipeline

Local / In Progress v4.0
What it does

A self-operating task scheduler where AI and ML do the work automatically. You define a task — the system assigns it AI-generated priority, schedules it via APScheduler, monitors your machine in real time using psutil, and runs three scikit-learn models continuously on live system metrics to detect anomalies, forecast resource usage, and predict task failure risk. A conversational AI chat agent lets you create tasks in plain English. Everything self-updates every 5 seconds.

Once running, the system operates autonomously — anomaly detection, failure prediction, and scheduling without manual intervention.
ML Pipeline — 3 Models on Live Data
1

Isolation Forest — Detects if current CPU/RAM/Disk metrics are anomalous compared to historical baseline

2

Linear Regression — Forecasts CPU% and RAM% 30 seconds ahead from live psutil stream

3

Random Forest — Predicts task failure probability based on system conditions at run time

System Architecture
1

16 async REST endpoints via FastAPI — modular files for monitor, scheduler, ML, AI, and calendar

2

Real-time data loop — psutil → metrics buffer → 3 ML models → API → Chart.js dashboard, every 5 seconds

3

LLM-powered task creation — Groq LLaMA 3.3 70B assigns priority, picks calendar time, runs AI health reports, and handles conversational task creation via chat bubble

4

Google Calendar integration — AI picks the optimal scheduling time and creates colour-coded events by priority (future work)

Tech Stack
FastAPI APScheduler scikit-learn Groq / LLaMA 3.3 psutil Chart.js SQLite Google Calendar API Railway

Project 03

Library Book Reservation System

FastAPI · React · SQLite · OpenAPI SDK · Pytest · Playwright

79 Tests Passing Hiring Challenge
What it does

A full-stack library reservation platform built as a hiring challenge. Users browse books, make reservations with 30-minute auto-expiry timers, and track status through a clean React UI. Librarians manage books and reservations through a role-restricted admin panel — all backed by a FastAPI REST API with Pydantic validation, SQLite, and a Python SDK generated from the OpenAPI spec.

The backend enforces a strict state machine: Pending → Confirmed → Cancelled/Completed. Invalid transitions are rejected with 400 errors — a classic trick requirement.
Key Engineering Details
79 Pytest backend tests (100% pass)
9 Playwright E2E UI tests
Auto SDK generated via OpenAPI Generator CLI
30m Reservation auto-expiry timer
System Architecture
1

FastAPI Backend — 12 REST endpoints with Pydantic v2 schemas, JWT auth, role-based access (user / librarian)

2

State Machine — Reservation lifecycle enforced server-side: Pending → Confirmed → Cancelled / Completed; invalid transitions return 400

3

OpenAPI SDK — Python client auto-generated from the live OpenAPI spec using openapi-generator-cli; no manual client coding

4

React Frontend — Vite + React with real-time reserve/cancel UX, faded button states, and auto-expiry countdown display

5

Testing — 79 Pytest unit + integration tests + 9 Playwright end-to-end UI tests covering all critical user flows
